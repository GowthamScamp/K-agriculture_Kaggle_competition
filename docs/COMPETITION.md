## 1. How games are scored - and why that is two different questions

Inside a game, the winner is whoever ends the season with the most coins.
`ENVIRONMENT.md` records the env's own reward as *"Player money at end of game
(final score)"*, and `task.md` describes the score the same way.

On the **ladder**, that is not how an agent is rated:

> "Winning the match (having the most coins in the bank at the end of 720 turns)
> increases your skill rating, while losing decreases it. The amount your rating
> changes depends on the rating difference between you and your opponent. [...]
> **The actual coin difference in a match does not affect the rating change -
> only the win, loss, or tie outcome matters.**"

And the final standings are not the running rating either:

> "A final Bradley-Terry tournament will be run on those episodes to produce the
> final leaderboard."

**Consequence for this project.** The quantity to maximise is P(win), not
E[coin margin]. An agent that wins 92 games out of 100 by a nose outranks one
that wins 86 by a landslide. Every result reported here is therefore led by
**win rate with a Wilson interval**, and agent-vs-agent comparisons use an exact
**McNemar** test on the seeds where the two disagree. Coin margin is still
reported, as effect size - it explains *how* an agent wins - but it does not
decide anything. `src/evaluate.py` had this backwards until 23 Aug 2026.

Ties are possible (the env README says so, and 7 of 100 `baseline` self-play
seeds ended level). They count as half a win, per the Bradley-Terry convention.

## 2. Submitting

> **Confirmed from the live submission dialog, 30 Aug 2026.** This section is
> the one part of this file backed by the actual UI rather than by search-snippet
> extraction, so it is the most reliable thing here. An earlier revision stated
> the archive rule as if it were universal and claimed `.tar.gz` was preferred;
> both were wrong.

Verbatim from the dialog:

> "Your submission should be a python file with the **last 'def'** accepting an
> observation and returning an action. You can also upload multiple files in a
> **zip/gz/7z** archive with a `main.py` at the top level."

**These are two different binding rules, and which one applies depends on what
you upload.**

| Upload | Entry point resolved by | Failure mode if wrong |
|---|---|---|
| bare `.py` | **the last `def` in the file** — positional | binds a helper instead of the agent; silent |
| `.zip` / `.gz` / `.7z` | **`main.py` at the top level** — by name | archive rejected, or entry point not found |

The positional rule is the dangerous one for this project. `submission/main.py`
is a generated flattening of four modules with many top-level `def`s; `agent` is
last only because `tools/build_submission.py` appends its `FOOTER` last. Nothing
about that is structural, and `hasattr(module, "agent")` cannot detect a
violation — it stays true while Kaggle binds something else entirely.

**The precise runtime rule** (read from `kaggle_environments/agent.py`,
`get_last_callable`, 27 Sep 2026): the file is exec'd into a dict and the entry
point is `[v for v in env.values() if callable(v)][-1]` - the last *callable
inserted* into the namespace. A redefined name keeps its original slot, and any
callable assigned after `agent` (an alias, a class, an imported function) wins.
Wrappers must therefore `del agent` before redefining it, as the public tape
chassis do. `tools/verify_submission.py` now runs this exact function as a
blocker (`check_kaggle_binding`), in addition to the static last-`def` check.

So it is enforced, not assumed:

- `check_entry_point_contract()` in `tools/verify_submission.py` — a **blocker**
- `tests/test_submission_contract.py` — including a mutation test that appends a
  trailing `def` and requires the checker to reject it, so the gate is known to
  be capable of failing rather than merely observed to pass

**Both artifacts are built**, and they differ precisely in which rule they rely on:

- `submission/main.py` — the normal upload (134 KB)
- `submission/kaggriculture.zip` — identical bytes as `main.py` at the top level
  (34 KB); bound by name, so it is immune to the positional rule

For a genuinely multi-file submission the extracted files land in
**`/kaggle_simulations/agent/`**, so path-based loading would need to point
there. That does not arise here — the bundle is self-contained and
`tools/verify_submission.py` proves it imports with `src/` off `sys.path`.

## 3. The validation episode - agent versus itself

> "When you upload a submission, a Validation Episode is run where your agent
> plays against a copy of itself to ensure it runs without errors."

**This is the first thing that can reject a submission**, and it is the only
configuration in which *both* seats run the submitted policy. Every other local
gate pairs the agent against a cheap built-in opponent, which understates load. It is
therefore a blocking check in `tools/verify_submission.py`
(`check_self_play()`), which loads the bundle twice under different module names
so each seat gets its own agent instance, as two Kaggle processes would.

## 4. Submission and tracking limits

- Up to **5 submissions per day**. The dialog shows the remaining count and when
  it resets ("You have 5 submissions remaining today. This resets in 10 hours"),
  so the window is a rolling timer, not a calendar day — check it before
  planning a batch of uploads.
- Only the **latest 2** submissions are tracked, and those same two are used for
  the final leaderboard evaluation.
- The leaderboard shows only your best-scoring bot; the rest are visible on the
  Submissions page.

**Consequence, and it is the sharp edge here:** "latest 2" is positional, not
"best 2". Two careless uploads after a good one will push it out of the tracked
pair even if it outranks both. Do not submit anything untested close to the
deadline.

## 5. Timing

Per-turn and per-episode limits are introspected from the package and recorded
in [ENVIRONMENT.md](ENVIRONMENT.md#1-episode-and-limits): `actTimeout` 1 s,
`runTimeout` 1200 s, `remainingOverageTime` 60 s across the whole episode.

The submitted route performs no rollout search. The final artifact self-play
verification measured a 203 ms worst turn against the 1,000 ms action limit;
overage remains an emergency reserve, not planned headroom.
